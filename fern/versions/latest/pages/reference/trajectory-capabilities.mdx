# Trajectory capability matrix

<Warning>
A schema can represent evidence that a producer does not emit. The matrix reports producer coverage, not schema capacity.
</Warning>

## Acceptance criteria

| ID | Current support | Remaining limitation |
|---|---|---|
| C1 — standard model-call schema | `ng_trajectory.model_calls` uses standard token names, timing, status, request/response, and response metadata | Custom and direct-provider integrations must expose their calls to rollout collection |
| C2 — complete token statistics | Shared capture and Responses conversion preserve provider-reported prompt, completion, reasoning, total, and cached counts | Inference Provider, Anthropic conversion, and custom adapters can still expose partial usage or API defaults |
| C3 — standard per-turn fields | Turns contain task and rollout identity, turn number, timestamp, question, answer, reasoning content, resolution, and cumulative step count | Turn fidelity depends on exact producer ownership and history evidence |
| C4 — reconstruct model-visible history | Captured model-server exchanges and the root invocation conversation are copied into `ng_trajectory` | Provider rendering, direct-provider calls, child invocations, stateful context, and incomplete compaction boundaries remain gaps |
| C5 — complete tool observations | Simple Agent and Claude Code tool attempts contain output, status, timestamps, duration, and errors | Most agents do not yet emit shared tool observations |
| C6 — parallel tool timing | Independent tool-attempt intervals represent overlap | Producer coverage is limited; Simple Agent executes tools sequentially |
| C7 — resource and sandbox integrations | Simple Agent is the resource-server reference; Claude Code is the custom/sandbox reference | Other CLI, remote, imported, and sandbox-backed producers remain partial |

Rollout collection adds `ng_trajectory` when model-call capture or agent observations are present. Model-call evidence
requires calls to use a rollout-prefixed Gym Model Server with capture enabled.

Capture-backed C1, C2, and C4 require `observability_enabled` and rollout-prefixed Gym Model Server requests. Direct
provider calls are not captured. C7 requires an agent-side shared observation producer; model HTTP capture alone does not
satisfy it. None of #2115–#2120 emits canonical `TrajectoryTurn` records, so those pull requests do not satisfy C3.
Open C5 entries must populate `ToolCallObservation.output` when rebased onto the current contract.

Trajectory consumers must distinguish unavailable values from measured zeros.
